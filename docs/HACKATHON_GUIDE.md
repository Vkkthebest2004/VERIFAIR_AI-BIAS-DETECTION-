## 1. What is Verifair?

Verifair is a **full-stack AI platform** that reads any document (PDFs, CSVs, or raw text) and automatically detects hidden biases — including hate speech, stereotypes, and unfair treatment. Think of it as a **bias scanner for text**, like how an antivirus scans files for threats.

**In one sentence:** *Upload a document, and Verifair tells you exactly where bias exists, how severe it is, who it affects, and explains it in plain English.*

---

## 2. The Problem We Solve

AI systems and human-written documents often contain **hidden biases** that discriminate against people based on gender, race, age, religion, disability, or sexual orientation. These biases show up in:

- **HR Policies & Job Descriptions** — wording that discourages certain groups from applying
- **Loan & Insurance Documents** — language that treats different demographics unfairly
- **Performance Reviews** — vague, subjective feedback given differently based on identity
- **AI Training Data** — datasets that embed societal prejudices into machine learning models

**Real-world impact:**
- Amazon's AI hiring tool was scrapped because it penalized resumes containing the word "women's" (Reuters, 2018)
- ProPublica showed COMPAS crime prediction software was twice as likely to falsely flag Black defendants (2016)
- A Stanford study found GPT-3 associated "Muslim" with "terrorism" 23% of the time (Abid et al., 2021)

Verifair catches these problems **before** they cause harm.

## 3. How It Works — The Big Picture

Here's the entire flow explained simply:

```
                UPLOAD                        PROCESS                         RESULTS
        ┌─────────────────┐          ┌──────────────────────┐         ┌─────────────────────┐
        │  User uploads   │          │  VerifairSentinel    │         │  Interactive         │
        │  PDF / CSV /    │  ──────> │  Engine runs 6       │ ──────> │  Dashboard shows     │
        │  Text files     │          │  analysis layers     │         │  findings + AI       │
        │                 │          │  on every sentence   │         │  explanations        │
        └─────────────────┘          └──────────────────────┘         └─────────────────────┘
```

**Step 1:** User uploads a file or types text on the frontend.

**Step 2:** The backend extracts text from the file (using pdfplumber for PDFs, pandas for CSVs), splits it into sentence-level chunks of 3 sentences each, and sends each chunk through the VerifairSentinel engine.

**Step 3:** The Sentinel engine runs **6 independent analysis layers** on each chunk:
  1. Z-Score Bias Detection (statistical)
  2. WEAT/SEAT Tests (association measurement)
  3. Stereotype Detection (13 categories)
  4. Hate Speech Detection (3-layer neural ensemble)
  5. Advice Disparity Analysis (differential treatment detection)
  6. Quality Analysis (vagueness/subjectivity scoring)

**Step 4:** Results are saved to a database and displayed on an interactive dashboard with charts, severity scores, and plain-English explanations generated by Llama 3.2.

## 5. The 6 Core Analysis Engines

This is where the actual AI magic happens. Each engine runs independently on every text chunk.

### Engine 1: Z-Score Bias Detection

**What it does:** Measures how closely a piece of text is semantically associated with different identity groups (Male, Female, Black, White, Muslim, etc.) using vector embeddings.

**How it works:**
1. The text is converted to a 768-dimensional vector using `all-mpnet-base-v2` (a sentence-transformer model).
2. We pre-compute embeddings for 13 identity terms (Male, Female, LGBTQ, etc.).
3. We calculate the **cosine similarity** between the text and each identity.
4. We compute the **Z-score** — how many standard deviations the similarity is from the mean of neutral text.
5. We also compute **Cohen's d** (effect size) for robustness.

**Example:** The text *"Women are too emotional for leadership"* would have a very high cosine similarity with "Female" and a high Z-score, flagging it as biased.

### Engine 2: WEAT / SEAT Tests

**What it does:** Measures if a text has a positive or negative emotional association using a standard psychology test adapted for AI.

**How it works:**
1. Based on the **WEAT** (Word Embedding Association Test) by Caliskan et al. (2017).
2. We define two word lists: **Pleasant** (love, joy) vs. **Unpleasant** (hate, evil).
3. We calculate the differential association of the text with these two lists.
4. **Positive score** = Pleasant association; **Negative score** = Unpleasant association.

### Engine 3: Stereotype Detection (13 Categories)

**What it does:** Checks if text contains patterns matching known stereotypes across 13 protected categories.

**How it works (two-dimensional):**

**Dimension 1 — Neural Toxicity (toxic-bert):**
Checks for toxicity, identity hate, insults, and threats using a BERT model.

**Dimension 2 — Embedding Similarity:**
Compares text against 13 stereotype concept clusters (e.g., "Gender Occupation", "Race Competence", "Age Capability").

**Composite Score:** Combines toxicity, embedding similarity, and severity weights (0.6 to 1.0) into a final 0-100 score.

### Engine 4: Hate Speech Detection (3-Layer Ensemble)

**What it does:** Detects explicit, implicit, and coded hate speech using three independent neural models.

**The 3 Layers:**
1. **Dynabench RoBERTa:** Explicit hate speech.
2. **ToxiGen RoBERTa:** Implicit/coded hate (higher weight).
3. **Lexicon & Embeddings:** Slurs, dehumanization, symbols.

**Ensemble Scoring:** Weighted average of the three models.

### Engine 5: Advice Disparity Analysis

**What it does:** Detects when text gives different quality of advice based on someone's identity.

**How it works:**
Compares text against clusters of **Positive**, **Negative**, **Conditional**, and **Directive** advice. Flags if identity terms are paired disproportionately with negative/conditional advice.

### Engine 6: Quality / Vagueness Analysis

**What it does:** Scores how vague or subjective the text is (0-100).

**Concept clusters:** 
- **Vague:** "attitude", "culture fit", "vibe"
- **Subjective:** "too much", "hard to explain", "just a feeling"

## 6. Mathematical Foundation

For the judges who want to see the math, here are the exact formulas driving Verifair's analysis:

### A. Semantic Similarity (Cosine)
We measure the angle between the **Target Text Vector** ($t$) and **Identity Concept Vectors** ($i$) within our 768-dimensional embedding space:

```math
sim(t, i) = \frac{t \cdot i}{\|t\| \|i\|}
```

### B. Statistical Bias (Z-Score)
To filter out noise, we normalize similarity scores against a baseline distribution derived from neutral business text:

```math
Z = \frac{x - \mu_{baseline}}{\sigma_{baseline}}
```
*   **Threshold:** We flag bias only when $|Z| > 2.0$ (approx. 95% confidence interval).

### C. Effect Size (Cohen's *d* & Hedges' *g*)
We calculate the *magnitude* of bias, correcting for small sample sizes using Hedges' correction:

**Cohen's *d*:**
```math
d = \frac{\bar{x}_1 - \bar{x}_2}{s_{pooled}}
```

**Hedges' *g* Correction:**
```math
g \approx d \times (1 - \frac{3}{4(n_1 + n_2) - 9})
```

### D. SEAT (Sentence Embedding Association Test)
Measures the differential association between a target sentence ($w$) and two attribute sets (Pleasant $A$ vs. Unpleasant $B$):

```math
s(w, A, B) = \text{mean}_{a \in A} \cos(w, a) - \text{mean}_{b \in B} \cos(w, b)
```

### E. Hate Speech Ensemble Scoring
Our final hate speech confidence score ($S_{final}$) is a weighted ensemble designed to prioritize implicit hate detection:

```math
S_{final} = (0.35 \times P_{Dynabench}) + (0.40 \times P_{ToxiGen}) + (0.25 \times P_{Lexicon})
```
*   **$P_{ToxiGen}$ (0.40):** Highest weight because detecting implicit hate is our competitive advantage.

## 8. Key Features

### Multi-Input Batch Analysis
Upload multiple files (PDF, CSV, TXT) and/or enter multiple text inputs simultaneously. The system:
- Analyzes each input independently
- Creates a **Batch Summary Report** that merges all results
- Generates an executive conclusion using Llama 3.2
- Tags each result with its source file for traceability

### Interactive Visualizations
- **Gauge Chart:** Overall hate speech score (0-100%) with color-coded severity
- **Bar Chart:** Breakdown by analysis layer (Dynabench, ToxiGen, Lexicon)
- **Radar Chart:** Multi-dimensional hate type profile
- **Topic Distribution:** What topics the text covers (Risk, Competence, Sentiment)

### Sensitivity Control
Users can adjust the Z-score sensitivity threshold (1.0 - 3.0) with a slider to control how strict the detection is. Lower = catches more subtle bias. Higher = only flags severe bias.

### LLM-Powered Explanations
Every flagged text gets a plain-English explanation from Llama 3.2, addressed to a non-technical HR manager. No jargon, just clear reasoning about why the text is problematic.

### Selection Bias Module
A separate page for CSV data analysis:
- Upload a CSV with candidate data (demographics + outcomes)
- Computes **Four-Fifths Rule** violations (EEOC standard)
- Calculates **Adverse Impact Ratios** per group
- Runs **Chi-Square** independence tests
- Uses **Fairlearn** for demographic parity metrics

### User Authentication
Full JWT-based auth system: register, login, and all API calls require a Bearer token. Passwords are hashed with bcrypt. Tokens expire after a configurable period.

## 9. Data Flow — Step by Step

Here is what happens when you click "Run Bias Audit":

```
1. FRONTEND: User drops files / enters text
   └──> DragDropUpload.tsx collects files[] and textInputs[]
   └──> page.tsx creates FormData: files + text as .txt Blobs
   └──> POST /api/v1/audit (with JWT Bearer token)

2. BACKEND: routes.py receives the request
   └──> Validates files (filters empty UploadFile entries)
   └──> For each file:
        ├── PDF → pdfplumber extracts text
        ├── CSV → pandas reads rows, joins columns per row
        ├── TXT → decode as UTF-8
        └── Unknown → try as text (fallback)

3. BACKEND: IngestionService.clean_and_chunk_text()
   └──> Cleans whitespace
   └──> Splits into sentences (regex on . ! ?)
   └──> Groups into chunks of 3 sentences each

4. BACKEND: VerifairSentinel.batch_analyze(chunks)
   └──> For each chunk:
        ├── Convert text → 768-dim embedding (all-mpnet-base-v2)
        ├── Run Z-Score bias detection (13 identities)
        ├── Run SEAT analysis (pleasant vs unpleasant)
        ├── Run stereotype detection (toxic-bert + 13 categories)
        ├── Run hate speech (Dynabench + ToxiGen + Lexicon)
        ├── Run advice disparity analysis
        ├── Run quality/vagueness scoring
        └── Run topic categorization

5. BACKEND: ExplainerService.explain_bias()
   └──> For each biased chunk, call Llama 3.2 via Ollama
   └──> Returns plain-English explanation

6. BACKEND: Save to database
   └──> Create AuditRecord per file (SQLAlchemy → SQLite)
   └──> If multiple files: create Batch Summary with merged results
   └──> Generate batch executive conclusion via Llama 3.2

7. BACKEND: Return JSON response
   └──> Array of records, each containing:
        {filename, total_sentences, bias_flags_count, results[]}

8. FRONTEND: Redirect to /results/{record_id}
   └──> Fetch report from GET /api/v1/history/{id}
   └──> Render interactive dashboard with all findings
```

## 12. How to Run It

### Prerequisites
- Python 3.9+
- Node.js 18+
- Ollama (optional, for AI explanations)

### Option 1: Running with Docker (Easiest Way)
1. Install Docker Desktop.
2. Run this command in the project root:
   ```bash
   docker-compose up --build
   ```
3. Open `http://localhost:3000` in your browser.
4. That's it! The backend, frontend, and database are all set up automatically.

### Option 2: Running Locally (Manual Setup)

#### Backend
```bash
cd VERIFAIR
python -m venv backend/venv
source backend/venv/bin/activate
pip install -r backend/requirements.txt
# Run the NLTK downloader once:
python -m nltk.downloader punkt stopwords wordnet
uvicorn backend.main:app --reload
# Server runs on http://localhost:8000
```

#### Frontend
```bash
cd VERIFAIR/frontend
npm install
npm run dev
# App runs on http://localhost:3000
```

### Ollama (Required for AI Explanations)
regardless of how you run the app (Docker or Local), you need Ollama running on your host machine:
```bash
# Install Ollama from https://ollama.ai
ollama pull llama3.2
ollama serve
# Runs on port 11434
```
